# Master code prompt

This repository already implements this specification. Use the prompt below to rebuild
the app from scratch with an AI coding assistant, or paste it as context before asking
for new features so the assistant keeps the same rules.

````markdown
# ROLE
You are a senior Flutter engineer building a production mobile app for Android and iOS.
Write clean, idiomatic, well-tested Dart. Prefer the Flutter SDK over packages; every extra
dependency must justify itself.

# PRODUCT
"Gita for Everyone / सबके लिए गीता": a free, offline Bhagavad Gita app for people who
know little about the Gita. No ads, no accounts, no tracking, no data collection, no
internet access.

## Features
1. **Daily verse (Today tab).** The first time the app opens is Day 1. Day N shows the Nth
   verse of the daily sequence: all translated verses in reading order (1.1, 1.2, …).
   - Use calendar dates only, so time zones and daylight saving can never skip or repeat
     a day.
   - After the last translated verse, the sequence starts again at 1.1.
   - Readers can step back to earlier days and return to today.
   - Settings has "Start again from Day 1", with a confirmation dialog.
2. **Each verse shows:**
   - the speaker line if any (e.g. "Arjuna said");
   - the Sanskrit in Devanagari;
   - the pronunciation in IAST (can be switched off);
   - the Hindi translation;
   - the English translation;
   - an "In simple words" explanation in the interface language;
   - a "Draft translation, awaiting review" chip while unreviewed;
   - a copy button.
   If a verse has no translation yet, show the Sanskrit and say the translation is coming
   in a future update.
3. **Audio.** A listen/stop button on the Sanskrit, the Hindi and the English.
   - Use the phone's own text-to-speech (flutter_tts): Sanskrit and Hindi with hi-IN,
     English with en-IN, falling back to en-GB, then en-US. Slow speech is the default.
   - Only one thing plays at a time. Stop on page change, tab change and leaving the
     screen.
   - If no voice is installed, say so in a snackbar and explain how to add one.
   - Hide audio behind an interface (`VerseSpeaker`) so recorded audio can replace TTS
     later.
4. **Chapters tab.**
   - A list of the 18 chapters: number, title in the interface language, Sanskrit name,
     verse count.
   - Each chapter screen shows a plain summary and a verse list. Tapping a verse opens a
     swipeable reader with Previous/Next buttons and an "n / total" counter.
5. **Start here tab:**
   - "What is the Bhagavad Gita?", "Who's who" and "How to use this app";
   - a glossary of key words, in both languages.
6. **Settings tab:**
   - interface language (English / हिन्दी, with every interface string in both);
   - theme (auto/light/dark);
   - text size (0.85–1.6×, applied on top of the phone's own setting);
   - pronunciation on/off;
   - slow audio on/off;
   - restart from Day 1;
   - an about text saying the app is free, offline and collects no data;
   - open-source licences (`showLicensePage`).
   All settings are stored with shared_preferences.

## Content
All text comes from one bundled asset, `assets/content/gita.json`, generated by
`tool/build_content.py` from:
- `content/sanskrit.json`: 701 verses with chapter, verse, speaker, speakerIast, sanskrit
  and iast. The Sanskrit is public domain; the IAST is generated by our own converter.
- `content/chapters.json`: 18 chapters with Sanskrit name, English/Hindi titles and
  summaries.
- `content/learn.json`: speaker labels (Sanskrit → English/Hindi), learn sections and the
  glossary.
- `content/translations/chNN.json`: per verse english, hindi, simpleEnglish, simpleHindi,
  optional notes and wordMeanings, status (draft|reviewed), and reviewedBy (required when
  reviewed).
- The build validates everything and exits non-zero on errors.
- `--reviewed-only` drops unreviewed translations for store releases.
- Never include text from copyrighted translations.

# ARCHITECTURE
- Flutter stable, Dart 3, Material 3, saffron seed colour, light and dark themes.
- Runtime dependencies: only `shared_preferences`, `flutter_tts`, `share_plus` (share-as-image) and `url_launcher` (rate/contact links). No state-management
  package. Use an `InheritedNotifier` scope exposing the content, the SettingsController
  (a ChangeNotifier) and the VerseSpeaker.
- `lib/src/`:
  - `content/models.dart`: parsing and models;
  - `daily/daily_plan.dart`: pure date logic;
  - `settings/`;
  - `audio/`;
  - `l10n/strings.dart`: both languages, no codegen;
  - `ui/`: one file per screen, plus `widgets/`.
- A `SettingsController` takes an injectable clock, and the speaker is behind an
  interface, so everything is testable.

# SECURITY AND PRIVACY (non-negotiable)
- No network code. Release builds request no Android permissions; INTERNET appears only
  in the debug/profile manifests.
- Add `android:usesCleartextTraffic="false"`. Add the TTS_SERVICE `<queries>` intent for
  Android 11+.
- No analytics, ads, crash-reporting or remote-config SDKs.
- Release builds: R8 minify and shrink resources, `--obfuscate --split-debug-info`.
- Signing from an untracked `android/key.properties`. Git-ignore `*.jks`, `*.keystore`,
  `key.properties` and `.env`.
- iOS: set `ITSAppUsesNonExemptEncryption` to false, and add a PrivacyInfo.xcprivacy
  declaring no tracking and no collected data.
- Accessibility:
  - tooltips/semantic labels on all icon buttons;
  - respect the system text size;
  - verse text is selectable.

# TESTS (must pass in CI)
- **Unit:**
  - day-number maths, including daylight saving and a clock earlier than the start date;
  - day 1 → 1.1, day 2 → 1.2, and the wrap-around;
  - settings defaults, persistence and clamping;
  - content parsing (18 chapters, 701 verses, every daily verse fully translated).
- **Widget:**
  - Day 1 shows all three languages and the simple meaning;
  - the next day shows the next verse, and Previous day / Back to today work;
  - listen buttons call the speaker with the right language, and a missing voice shows
    the message;
  - switching to Hindi changes the interface;
  - chapters open, verses swipe, and untranslated verses show the "coming soon" text;
  - the Start here tab renders.
- **Python unittest for the content tools:**
  - IAST conversion;
  - import clean-up;
  - the build validates.

# CI (GitHub Actions, permissions: contents: read)
- **content job:** tool tests, rebuild the content and fail if `assets/content/gita.json`
  is out of date.
- **test job:** `flutter pub get --enforce-lockfile`, `dart format --set-exit-if-changed`,
  `flutter analyze`, `flutter test`.
- **android job:** release APK (debug-signed, test artifact only).
- **ios job:** `flutter build ios --no-codesign`.
- Dependabot weekly for pub and github-actions.

# DEFINITION OF DONE
`flutter analyze` is clean, all tests pass, CI is green on Android and iOS, there are no
TODOs in the code, and the README explains how to run, test, build content and release.
````
