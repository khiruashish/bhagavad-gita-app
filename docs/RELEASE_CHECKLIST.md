## 2. Content 🎓 🤖

- [ ] Scholar reviews the verses that will ship (all 701, or Chapters 1–3 for a phased launch). See GUIDE Step 5.
- [ ] Each approved verse has `"status": "reviewed"` and `"reviewedBy": "<name>"` in `content/translations/chNN.json`.
- [ ] Scholar also checks the Sanskrit against a printed edition (about 65 source typos are already fixed).
- [ ] Scholar checks the extra texts: 18 chapter summaries, "Start here", glossary, 58 quote topics (`content/quotes.json`), 12 situations (`content/situations.json`).
- [ ] Open questions flagged for the scholar: readings of 2.5, 9.32, 10.6; the words "outcaste"/"चाण्डाल" in 5.18.
- [ ] `python3 tool/check_similarity.py <reference dir>` reports **0 flagged** after any edit.
- [ ] `python3 tool/build_content.py --reviewed-only` passes, and the result has the verses you expect.
- [ ] With a reviewed-only build, Today, Quotes and Situations still have content. A situation needs at least 2 reviewed verses to appear; quotes appear only once reviewed.

## 7. Store forms and compliance 👤

Google Play:
- [ ] **Data safety**: no data collected, no data shared.
- [ ] **Content rating** questionnaire (reference / religious text; expected "Everyone").
- [ ] **Target audience**: 13+ (choosing under-13 brings in the Families policy).
- [ ] **Ads**: "No ads".
- [ ] App category: Books & Reference (or Lifestyle). Tags.
- [ ] Contact details and privacy policy URL.
- [ ] If the account is personal and new: **closed test with at least 12 testers for 14 days** before production access (section 9).

Apple:
- [ ] **App Privacy**: "Data Not Collected".
- [ ] **Age rating** questionnaire (expected 4+).
- [ ] Export compliance: already answered in `Info.plist` (`ITSAppUsesNonExemptEncryption = false`).
- [ ] Privacy manifest included in the build (section 4).
- [ ] Category: Books or Reference.

## 8. Build and verify 🤖 👤

```bash
python3 tool/build_content.py --reviewed-only    # only reviewed verses ship
python3 -m unittest discover -s tool
flutter analyze && flutter test
flutter build appbundle --release --obfuscate --split-debug-info=build/symbols
flutter build ipa --release --obfuscate --split-debug-info=build/symbols   # on a Mac
```

- [ ] Version bumped in `pubspec.yaml`.
- [ ] Release APK/AAB has **no INTERNET permission** and no unexpected permissions (GUIDE Step 9 shows the `aapt2` command).
- [ ] `build/symbols` kept privately (needed to read crash reports).
- [ ] After the release, put `assets/content/gita.json` back to the full build (`python3 tool/build_content.py`) so the repo is not left with the reviewed-only file by mistake.
- [ ] Tag the release in git: `git tag v1.0.0 && git push origin v1.0.0`.

## 9. Testing 👤 + testers

- [ ] Play **internal testing**, then **closed testing** (12+ testers, 14 days for new personal accounts). Recruit testers early.
- [ ] Apple **TestFlight**: internal, then external (needs a short beta review).
- [ ] Testers check:
  - Day 1 shows 1.1; the next calendar day shows 1.2.
  - Reader: Next/Previous, chapter skip buttons, Continue reading.
  - Gita for my situation: every situation opens and has verses.
  - Share as image works with WhatsApp and Instagram; the picture is readable.
  - Listen works in Sanskrit, Hindi and English (or shows the "no voice" message).
  - Hindi interface, dark mode, largest text size.
  - Airplane mode: everything still works.
  - A small, older Android phone (Android 7–9) and an older iPhone (iOS 15).
- [ ] Fix anything found, rebuild, retest.

## 10. Submit and launch 👤

- [ ] Google Play: production release with a **staged rollout** (20% → 50% → 100%).
- [ ] Apple: submit for review (usually 1–3 days). Answer reviewer questions quickly.
- [ ] Pick a launch date. Gita Jayanti or Janmashtami are good moments.
- [ ] Announce: temples and satsang groups, WhatsApp, social media, GitHub README with store links.
- [ ] Update `README.md` with store badges and links.

## 11. After launch 👤 🤖

- [ ] Watch Play Console and App Store Connect for crashes and reviews weekly; reply to reviews.
- [ ] Ask happy users for a rating (in person, or a gentle in-app prompt after a week of use).
- [ ] Monthly content updates if launching in phases. Readers need each update before the daily sequence reaches the end of the shipped verses.
- [ ] Renew the Apple membership every year, or the app is removed from the App Store.
- [ ] Keep Flutter and plugins updated, and meet each year's Play target-API deadline.

## Definition of "ready to submit"

All of these are true:
1. Every shipped verse is `reviewed`, with 0 similarity flags.
2. Licences, credits, contact email and privacy policy URL are in place (section 1).
3. Real icon, feature graphic and screenshots from a reviewed-only build.
4. Signed release builds pass CI and the permission check.
5. Store forms complete (data safety / app privacy, ratings, audience).
6. Closed test / TestFlight done with no open serious bugs.
